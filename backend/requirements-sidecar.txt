# 客户端运行时（边车）的**真实依赖**清单 —— P4-3
#
# ## 这份清单是**算出来的**，不是"看出来的"
#
# 口径：**以 `import app.sidecar` 的实测 `sys.modules` 为准** ——
# 只读脚本 `scripts/sidecar-closure.py`（不装包 / 不打网络 / 不改运行时 / 不杀进程）。
# 上一版的教训：靠"读代码看它 import 了什么"写出来的清单**不等于**真实闭包 ✗，
# 四轮实测各逼出一个缺项（`typing_extensions` 单文件 .py → `_cffi_backend` 根 .pyd →
# `pydantic_settings` → `jieba`）—— **清单 ≠ 闭包** ✓。
#
# ## Phase B：把"客户端用不到的服务器后端"从闭包里赶出去
#
# 惰性化的那一刀落在 `app/core/storage.py`（"唯一允许 import 具体实现"的组合根）：
# 三个后端改成**按需导入**（只有 `build_stores()` 那一刻才 import）✓ ——
# 于是客户端那条装配路径（`sidecar.Clients` / `LocalServices`）永远不导入它们 ✓。
# 实测效果（同一脚本，改前 → 改后）：
#   顶层模块 **39 → 28**；这些全部从闭包里消失 ✓：
#   `psycopg` / `psycopg_binary` / `psycopg_pool`（约 9.5 MB）、`boto3` / `botocore` /
#   `s3transfer` / `jmespath` / `urllib3` / `six` / `python-dateutil`（约 21.8 MB）、
#   `duckdb` / `_duckdb`（约 35.6 MB）、`jieba`（约 40.9 MB）⇒ **约 108 MB 不再进客户端** ✓✓。
#
# ## 版本口径
# 全部从**当前开发 venv 实测**读出来（`importlib.metadata`），不是"最新版"；传递依赖也全部 pin。
#
# ## 离线装配的五种形态（都踩过）
# 1. **目录**（绝大多数包）；2. **单文件 `.py`**（`typing_extensions.py`）；
# 3. **site-packages 根下的 `.pyd`**（`_cffi_backend.cp312-win_amd64.pyd`）；
# 4. **伴生目录**（`*.libs/`，重型二进制包才有）；5. **`.dist-info/`（元数据）**。
# → 所以离线拷贝**按每个发行包的 `RECORD` 逐文件拷** ✓（RECORD 本身就是"这个包到底有哪些文件"的答案 ✓）。
#
# ## 红线
# 1. 绝不打包 dev venv（`backend/.venv`，约 400 MB）；
# 2. 绝不打包 LibreOffice（约 700 MB）—— 本机装了只"检测后使用"；
# 3. 不裁 `backend/app` 的源码（整份拷）；
# 4. 离线装配不拷 `*.chm`（pywin32 的 2.5 MB 帮助文件，运行期用不到）。
#
# ## 装法
# 联网：`powershell -ExecutionPolicy Bypass -File scripts\build-sidecar-runtime.ps1 -IndexUrl https://pypi.org/simple`
# 离线（推荐，从开发 venv 按 RECORD 拷）：`... -Offline`
# 本文件**存成 UTF-8 带 BOM**：pip 按本机 locale（GBK）猜编码，无 BOM 时中文注释会 UnicodeDecodeError（实测过）。
