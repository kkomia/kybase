01 / 工具面

十一个工具，
一圈走完。

上传、解析、管理、检索都在工具面里。Agent 不必知道背后的队列和索引，只要按状态往下走； 每一步都能调用、检查、重试。

    surface_fingerprint 覆盖工具名、描述、入参与返回；--list-tools 末行、serverInfo.version 与 GET /api/v1/tools 给的是同一个值。

    每个请求都要 Authorization: Bearer <API Key>，没有匿名放行。

    02 / 返回

    先给判定，
    再给原文。

    同一次检索里，summary 说清候选与收敛，distribution 给出分布和 fit， decision 记录为什么只回这几条；原文排在它们后面。

    • fit 四档：strong 对得上 · weak 对上一部分 · none 答不了 · unknown 判不了
    • score 是融合分，只反映名次；similarity 才是余弦
    • basis 标出这条是 vector 还是 fulltext 捞上来的

    03 / 页码

    页码，
    不是猜出来的。

    解析产物把页边界写成 <!-- page:N -->。切块器只在页标记与总页数自洽时，才把页码挂到块上； 对不上，就回 null。报一个翻不到的页码，比不报更糟。

    01

    解析时，页边界写进 Markdown

    MinerU 的 content_list 给出页码顺序，页标记插在合并产物的正确位置；纯文本与 Office 本来就没有页，如实留空。

    02

    切块时，页码跟着块走

    一个页码可信，当且仅当它后面紧跟着下一页标记，或它就是总页数。标记号倒退、与页数对不上，整篇都不给页码。

    03

    检索时，带着页码回来

    命中里有原文切片、页码与标题路径，还有 chunk_id 便于复现。PDF 还能按页取回原图——图、表、版式都在原位。

    get_document_pages 一次可取 1–50 页：每页给解析文字；PDF 与图片类还给这一页原图的签名链接。 页标记不可信时 pages_reliable 为 false，这时别拿它当「第 N 页」引用。

    05 / 调参

    策略不是预设，
    是这一次的参数。

    没有 fast / balanced / precise 的档位。检索模式三档、参数逐次给；分布顺手返回 suggested， Agent 可以照建议收，也可以自己改，再用 next_offset 翻完。

    distributionSTRONG
    38 candidates · 4 survived
    0.37baseline 0.5310.712
    资料很对得上，按每篇最相关的收敛。

    分布、基线、建议值都在同一次返回里；fit=none 时建议 keep=0，如实说没有。

    mode
    向量 + 词面，RRF 融合
    keep 4 一页回几条
    min_score 0.531 绝对余弦下限
    per_doc null 每篇最多几条
    decided_by suggested 谁给的这三个数

    下一次调用

    {"keep": 4, "min_score": 0.531, "per_doc": null}

    按分布建议收。三个旋钮原样带回，翻页时判定不变。

    min_score 只切向量通道；词面命中没有余弦可比，条数记在 decision.unscored_kept，要更严就自己按 lexical_score 筛。

    offset / next_offset 翻的是「幸存者」名单；越过末尾不是错，回空 hits 和 next_offset: null。
