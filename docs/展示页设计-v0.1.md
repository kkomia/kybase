# kybase 展示页设计 v0.1

> 2026-10-22 · 读者：维护展示页的人、想知道「为什么长这样」的人。
> 展示页源码在仓库 `site/`，线上地址 <https://kkomia.github.io/kybase/>。
> 管理台自己的设计约定在 [`界面设计-v0.2.md`](界面设计-v0.2.md)，本文只管**对外展示页**。

## 1. 任务与边界

老板的原话：**「以大师水准设计一个 GitHub Page，充满动感，让人感到舒服而不花哨」**，
沿用产品已经定下来的「纸与墨 · 信号蓝」，发布到 GitHub Pages。

先把品类认清楚：这不是 SaaS 营销页，是一个**自托管基础设施项目的门面**。来访者是工程师，
通常从 README 点进来，前几秒要回答三个问题：「它是什么」「跟我现有的东西怎么接」
「我现在能不能跑起来」。所以：

- 首屏必须在**一句话内**说清「返回带出处的原文片段，而不是生成的回答」；
- 要给出**只有这个产品才有的证据**——判定先于原文、页码只在能核对时出现、收敛与翻页；
- 要用**真实运行界面**做可信度，不用插画和虚构指标；
- 动效为「让人相信它是活的」服务，不为炫技服务。

边界：纯静态、无构建步骤；不加载外部字体与 CDN；支持 390px 窄屏与
`prefers-reduced-motion`；中文正文、技术词用等宽字体；页面任何地方只出现 kybase 这一个名字。

## 2. 方向：安静的实验室，活着的仪表

| 维度 | 决定 |
| --- | --- |
| 北极星 | **安静的实验室，活着的仪表**：纸是安静的，仪表是活的 |
| 纸 | 暖纸底 `#f2efe9`、内容卡 `#fffdf9`；深色是 `#0d0e10` / `#16181c` 三层明度 |
| 墨 | 文字 `#14161a`、次级 `#3d3b36`、元信息 `#5f5a50`（对纸 ≥ 4.5:1） |
| 信号蓝 | `#2f54eb`，只给「动作 / 当前 / 数据」；深色提到 `#8098ff`，按钮文字转墨色 |
| 字 | 系统无衬线（与原产品一致）；数据、路径、代码用等宽字体；标题 600 字重、负字距 |
| 层级 | 靠字号、留白、一道极浅投影；正文不用满屏灰线分割 |
| 图形 | 只用两种：**文档纸**（sheet）与**仪表**（判定条、分布、命中行）；不用漂浮几何与渐变球 |

「纸」的隐喻贯穿整页：首屏右侧是一张检索判定的响应纸；滚动叙事里是一张文档纸被切成
纸片、再收成命中行、最后抽出一条引用；管理台截图标成「图版 NN」；页脚是版权页。

## 3. 页面结构与每一段在做什么

| 段 | 内容 | 目的 |
| --- | --- | --- |
| 顶栏 | 行星字标 + 5 个锚点 + GitHub + 明暗切换 | 随时可跳转，不抢首屏 |
| 首屏 | 「让每一句引用，都翻得到原文。」+ 检索判定卡片 + 管理台图版 | 3 秒内说清产品语义；判定卡片是唯一的「主视觉」 |
| 主张 | 「回答可以生成，出处不能。」 | 一句话把立场说透，作为段落间的呼吸 |
| 能力 | 判定先于原文 / 页码只在能核对时出现 / 收敛是一页一页翻 | 产品最硬的三条语义，各配一个微型示意图 |
| 过程 | 四步吸附叙事：摄入 → 切块 → 检索 → 引用 | 全页唯一的滑动驱动叙事，主角是「一张纸」 |
| 接入 | MCP / REST / Skill 三个标签页 + 可复制片段 + 鉴权说明 | 工程师最关心的落地路径 |
| 界面 | 概览 / 知识库 / 库详情 / 模型 / 深色五张真实截图 | 证明界面存在且做得下去 |
| 部署 | 四个决定 + 一条命令 + 如实标注「四件套尚未实测」 | 给出下一步，不藏限制 |
| 页脚 | 字标、文档链接、MIT、版权 | 收束 |

**首屏判定卡片**是全页的主角：它同时承担主视觉与产品说明。卡片的层次是
「请求行 → 查询 → 判定（fit 印章 + 分布条 + 收敛参数）→ 命中行」，
顺序与真实响应**逐字一致**（判定排在原文之前），不是装饰排版。

## 4. 动效

规则：只动 transform / opacity；不做视差装饰；所有动效在
`prefers-reduced-motion: reduce` 下直接到位，内容一样不少。

| 位置 | 动效 | 时长 / 手感 |
| --- | --- | --- |
| 首屏标题 | 两行从遮罩里升起，字距从略松收紧 | 950ms，120ms 错开，缓出 |
| 判定卡片 | 查询逐字打出 → 分布条从底部生长 → `strong` 印章轻微过冲落下 → 命中行依次落位 | 打字 62ms/字；条 550ms；印章 420ms |
| 主张 | 逐字亮起（滚动触发，只播一次） | 每字 35ms |
| 分区 | 标题与正文按阅读顺序上浮 24px 淡入；图版上浮 34px 淡入 | 750–900ms，只播一次 |
| 吸附叙事 | 滚动位置 1:1 驱动：纸淡出 → 六张纸片升起 → 收成命中行 → 抽出一条引用；步骤条与章节文字同步 | sticky + GSAP ScrollTrigger scrub 0.6 |
| 按钮 / 复制 | 悬停抬 1px、按下缩 1.5%；复制成功按钮变「已复制」 | 160–200ms |
| 主题切换 | 全页令牌瞬切（不做整页转场，避免闪烁） | 即时 |

**为什么用吸附叙事**：产品的核心过程是「一张文档变成一条可引用的证据」，这是一段有方向、
有终点的形变，正好适合「主角在滚动里发生明显变化」的手法；它比再加三张卡片更能让人记住
这个产品到底在做什么。手机上不 pin，把同一段摊成「最终态 + 四段说明」，保证可读。

## 5. 内容与口径

- 判定卡片、叙事里的数字（候选 38 / 保留 5 / 0.71 / p.7）是**演示数据**，不冒充业务指标；
- 管理台截图来自作者自托管实例的数据副本，知识库与文档名已换成演示内容；
- 「四件套 compose 尚未在干净机器上整体实测」这句**必须留着**——它和产品「出处诚实」的
  主张是同一件事；
- Skill 段不提具体目录名（配置分家还没做），只展示「纯 REST；先读判定，再读原文」的结构；
- 页面不出现旧名 kylab。

## 6. 技术与文件

```
site/
  index.html      语义结构 + 全部文案
  styles.css      令牌、布局、组件、响应式、深色、减少动态
  app.js          主题、判定演示、GSAP 动效、接入标签页、复制、当前分区
  vendor/         GSAP 3.13.0 + ScrollTrigger（固定版本随仓库提交）
  assets/         五张真实界面截图、og.png（社交卡片）、favicon.svg
  README.md       本地预览与 Pages 发布说明
.github/workflows/pages.yml   推送 site/ 即部署
```

调试参数：`?motion=off` 静态/减少动态版本，`?smooth=off` 关闭平滑滚动（截图取证用）。

## 7. 验收与评审

- 视口：1440×900（浅 / 深）、390×844、900×900、200% 缩放；
- 交互：登录/无登录无关，检查判定卡重放、接入标签页键盘左右键、复制反馈、锚点跳转、
  主题切换记忆、刷新后主题保持；
- 动画：从头滚到底再滚回去，确认叙事可倒放、文字在静止时出现、减少动态下内容完整；
- lint：`oil_ui_shoot` 的默认做法提示——保留项是「卡片里套卡片（sheet 在 stage 里）」，
  理由见 §2（工作台面与台上的纸是两种材质）；其余可读性问题已清零；
- 独立评审：无历史上下文的评审者，只看截图、任务与约束，10 分制打分并给问题清单；
  记录见 `ui-work/`（gitignore），结论同步到本文 §7 与交接文档。

## 8. 维护提示

1. **别把纸改成玻璃**：新加区块先问「它是纸、是仪表、还是空白」，不要引入玻璃拟态与渐变；
2. **蓝色只给三处**：动作、当前、数据。装饰用蓝色会立刻破坏层级；
3. **改文案先改口径**：产品语义（判定先于原文、页码规则）变了，先改 §5 与 README，再改页面；
4. **截图更新**：管理台改版后用一次性数据副本重拍，别把真实知识库名带进公开仓库；
5. **动效新增**：必须能回答「它承担反馈 / 引导 / 连续 / 品牌表达里的哪一项」，
   否则不加；新增后回归减少动态与窄屏；
6. **Pages 发布**：推 `site/` 改动即可；资源路径必须保持相对（站点挂在 `/kybase/` 子路径）。
