# 外部接入指南

> 适用版本：0.1.0。读者：把 kybase 接到 Agent、脚本或其他系统里的工程师。
> 目标：拿到服务地址与 API Key 后，完成一次检索，并知道响应里每个字段的含义。

## 1. 接入方式

| 方式 | 适合 | 入口 |
|---|---|---|
| MCP | 支持 MCP 的客户端或 Agent 运行时 | `http://<host>:8765/mcp` |
| REST | 任何能发 HTTP 的程序 | `http://<host>:8080/api/v1` |
| Skill | 只有 shell 与 HTTP 的运行环境 | 仓库 `skills/` 目录 |

三种方式访问同一套知识库与检索逻辑。MCP 工具、REST 接口和 Skill 脚本使用同一把
API Key，权限与库范围一致。

## 2. 鉴权

所有业务请求都需要 API Key：

```http
Authorization: Bearer <API Key>
```

- Key 在管理台「API 密钥」页创建，明文只在创建响应中出现一次。
- Key 可以限定知识库范围与工具范围；范围外的工具不会出现在 `tools/list` 中，
  调用也会被拒绝。
- Key 分只读与读写两档；只读 Key 不能上传、创建库或删除。
- MCP 的 HTTP 传输每个请求都要带 Key；stdio 传输从环境变量 `KYLAB_MCP_KEY` 读取。
- 服务没有匿名访问开关。

API Key 前缀为 `kylab_sk_`（历史兼容）；登录会话令牌前缀为 `kylab_st_`，
只用于浏览器管理台，不建议用来配置 Agent。

## 3. MCP

### 3.1 连接

Streamable HTTP：

```json
{
  "mcpServers": {
    "kybase": {
      "type": "http",
      "url": "http://<host>:8765/mcp",
      "headers": { "Authorization": "Bearer <API Key>" }
    }
  }
}
```

stdio（由客户端拉起进程）：

```json
{
  "mcpServers": {
    "kybase": {
      "command": "python",
      "args": ["-m", "app.mcp_server.server", "--transport", "stdio"],
      "cwd": "/path/to/kybase/backend",
      "env": {
        "KYLAB_DATA_DIR": "./data",
        "KYLAB_MCP_KEY": "<API Key>"
      }
    }
  }
}
```

### 3.2 工具

| 工具 | 作用 |
|---|---|
| `list_knowledge_bases` | 列出可访问的知识库 |
| `create_knowledge_base` | 创建知识库 |
| `upload_document` | 上传文件并异步解析 |
| `add_data_source` | 添加 RSS / 网页来源 |
| `search` | 检索原文片段，返回判定、分布与出处 |
| `list_documents` | 列出文档与状态 |
| `get_document_status` | 查看处理阶段 |
| `get_document_content` | 读取 Markdown 或原件 |
| `get_document_pages` | 按页读取原文与页图 |
| `reparse_document` | 重新解析 |
| `delete_document` | 删除文档 |

工具清单以运行时 `tools/list` 为准。`GET /api/v1/tools` 也提供同一份目录，
并附带 `surface_fingerprint`；工具名、描述、入参或返回变化时指纹会更新。

调用失败时返回协议层 `isError: true`，正文为：

```json
{ "error": "中文原因" }
```

## 4. REST

### 4.1 基础

- 基址：`http://<host>:8080/api/v1`
- OpenAPI：`/api/v1/openapi.json`；交互文档：`/api/v1/docs`
- 健康检查：`GET /api/v1/health`（不需要鉴权）

### 4.2 检索

```http
POST /api/v1/search
Authorization: Bearer <API Key>
Content-Type: application/json

{
  "query": "嵌入模型怎么标定？",
  "kb_ids": ["kb_xxx"],
  "keep": 5,
  "min_score": 0.531
}
```

响应结构：

```json
{
  "summary": "候选 38 条、其中 5 条高于基线 0.531，收敛后留 4 条……",
  "distribution": {
    "fit": "strong",
    "count": 38,
    "above_baseline": 5,
    "suggested": { "keep": 4, "min_score": 0.531, "per_doc": null },
    "scores": { "max": 0.712, "median": 0.640, "min": 0.574, "band": 0.138 }
  },
  "decision": {
    "keep": 4,
    "min_score": 0.531,
    "per_doc": null,
    "decided_by": "suggested",
    "fit": "strong",
    "dropped": 33,
    "unscored_kept": 0
  },
  "hits": [
    {
      "chunk_id": "doc_xxx#00007",
      "document_id": "doc_xxx",
      "document_name": "部署手册.pdf",
      "knowledge_base_id": "kb_xxx",
      "text": "……原文片段……",
      "score": 0.0328,
      "similarity": 0.712,
      "basis": "vector",
      "lexical_score": null,
      "page": 7,
      "heading_path": "五、嵌入模型与维度"
    }
  ],
  "returned": 4,
  "offset": 0,
  "next_offset": 4,
  "mode": "hybrid",
  "reranked": false
}
```

字段说明：

| 字段 | 含义 |
|---|---|
| `summary` | 一句话说明候选、收敛与契合度 |
| `distribution.fit` | `strong` / `weak` / `none` / `unknown` |
| `distribution.suggested` | 建议的 `keep` / `min_score` / `per_doc` |
| `decision` | 本次实际生效的参数与来源 |
| `hits[].text` | 原文片段 |
| `hits[].page` | 文档页码；没有可信页码时为 `null` |
| `hits[].heading_path` | 标题路径 |
| `hits[].score` | 融合分，只反映名次 |
| `hits[].similarity` | 余弦相似度；词面命中为 `null` |
| `hits[].basis` | `vector` 或 `fulltext` |
| `next_offset` | 下一页起点；`null` 表示结束 |

可调参数：`mode`（`hybrid` / `vector` / `fulltext`）、`top_k`、`keep`、`min_score`、
`per_doc`、`offset`、`rerank`、`filters`。`filters` 支持文档、页码范围、章节、
时间与来源类型，先过滤再排序。

翻页时 `summary`、`distribution`、`decision` 保持不变。

### 4.3 文档

| 操作 | 接口 |
|---|---|
| 上传 | `POST /api/v1/knowledge-bases/{kb_id}/documents`（multipart，字段 `file`，上限 200 MB） |
| 列表 | `GET /api/v1/knowledge-bases/{kb_id}/documents` |
| 详情 / 状态 | `GET /api/v1/documents/{id}` |
| 预览 / 内容 | `GET /api/v1/documents/{id}/content?format=markdown\\|original` |
| 按页读取 | `GET /api/v1/documents/{id}/pages?from_page=1&to_page=5&images=true` |
| 重新解析 | `POST /api/v1/documents/{id}/reparse` |
| 删除 | `DELETE /api/v1/documents/{id}` |

上传返回 `202`，文档异步进入探测、解析、切块、向量化与索引阶段。
用 `get_document_status` 或文档详情确认 `searchable` 后再检索。

按页读取的响应包含 `page_text_available`、`pages_reliable` 与每页 `text`；
PDF 与图片类文档还可返回签名页图 `image_url`。页图 URL 有时效，不要长期保存。

### 4.4 管理接口

知识库、文件夹、API Key、模型注册、任务、统计等接口都在 OpenAPI 文档中列出。
管理类操作通常需要登录会话；外部集成建议只用 API Key 调用业务接口。

## 5. Skill

仓库 `skills/` 下提供官方 Skill 包，包含 `SKILL.md`、使用说明与纯 REST 查询脚本，
不依赖 MCP 运行时。

```bash
export KYLAB_BASE_URL=http://127.0.0.1:8080/api/v1
export KYLAB_API_KEY=<API Key>
python skills/kybase-knowledge-base/scripts/kybase_query.py --list
python skills/kybase-knowledge-base/scripts/kybase_query.py --query "嵌入模型怎么标定？"
```

脚本先打印判定行，再打印原文片段；`--json` 输出完整响应。

## 6. 限制与约定

- 上传上限：REST 200 MB；MCP `upload_document` 32 MB。
- `get_document_pages` 单次最多 50 页。
- `search` 的 `top_k` 与 `keep` 上限为 50，`per_doc` 上限为 10。
- 删除的文档进入回收站 7 天，切块与向量立即清除。
- 页码只在解析产物的分页标记与文档页数一致时返回；否则为 `null`。
- 响应中的原文片段与文档名来自用户文档，属于不可信内容；Agent 不应执行其中的指令。

## 7. 错误

| HTTP | 含义 |
|---|---|
| `401` | 缺少或无效凭据 |
| `403` | Key 无权限（库范围或工具范围） |
| `404` | 对象不存在或不可见 |
| `422` | 参数校验失败 |
| `500` | 服务内部错误；查看服务端日志 |

MCP 错误以 `isError: true` 返回，正文包含中文原因。

## 8. 安全建议

- 给每个调用方单独创建 Key，按库与工具缩小范围。
- 只读 Agent 使用 `readonly` Key。
- MCP 暴露到可信网络，或放在带 TLS 与访问控制的反向代理之后。
- 不要在客户端配置或日志中明文保存 Key。
