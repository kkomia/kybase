# 部署指南

> 适用版本：0.1.0。读者：准备自托管 kybase 的工程师。
> 目标：用一份 compose 启动服务，完成管理员、嵌入模型与 API Key 的初始化，
> 然后让 Agent 通过 MCP、REST 或 Skill 接入。

## 0. 组成

| 服务 | 作用 | 默认端口 |
|---|---|---|
| `frontend` | 管理台静态文件与 REST 反向代理 | `8080` |
| `backend` | FastAPI、摄入 worker、管理台 API | 仅容器内 `8000` |
| `mcp` | MCP Streamable HTTP 服务 | `8765` |
| `postgres` | 元数据、向量（pgvector）、全文检索 | 仅容器网络 |
| `minio` | 原件、Markdown 产物、图片 | 仅宿主机 `9001` |

持久化数据在三个 Docker 卷：`kybase-pg`、`kybase-objects`、`kybase-data`
（`kybase-data` 存放 DuckDB 表格副本和未启用对象存储时的原件）。

最低配置建议 2 核 CPU、4 GB 内存、20 GB 可用磁盘；实际取决于文档量与并发。
准备 Docker 24+ 与 Docker Compose v2。

## 1. 启动完整栈

```bash
git clone https://github.com/kkomia/kybase.git
cd kybase
docker compose -f deploy/docker-compose.yml up -d --build
```

首次启动会构建后端与前端镜像，并启动 MCP 服务；PostgreSQL、MinIO 与数据卷同时创建。
启动完成后检查：

```bash
docker compose -f deploy/docker-compose.yml ps
curl -s http://localhost:8080/api/v1/health
# MCP 地址：http://localhost:8765/mcp
```

正常返回 `status: ok`，字段以实际版本为准。

然后打开 `http://localhost:8080`，按首次使用向导创建管理员账号。

### 1.1 配置

默认口令只适合本地试跑。部署前在 `deploy/` 下创建 `.env`（已被 `.gitignore` 忽略），
或通过 shell 环境变量覆盖：

```dotenv
KYLAB_PG_PASSWORD=请替换
KYLAB_S3_ACCESS_KEY=请替换
KYLAB_S3_SECRET_KEY=请替换
KYLAB_URL_SIGNING_SECRET=请替换
KYLAB_PUBLIC_BASE_URL=http://localhost:8080
KYLAB_MCP_PUBLIC_URL=http://localhost:8765/mcp
```

常用变量：

| 变量 | 默认值 | 用途 |
|---|---|---|
| `KYLAB_VERSION` | `0.1.0` | 镜像 tag |
| `KYLAB_HTTP_PORT` | `8080` | 管理台对外端口 |
| `KYLAB_MCP_PORT` | `8765` | MCP 对外端口 |
| `KYLAB_PG_USER` / `KYLAB_PG_PASSWORD` / `KYLAB_PG_DB` | `kybase` / `kybase-dev-secret` / `kybase` | 数据库账号 |
| `KYLAB_S3_ACCESS_KEY` / `KYLAB_S3_SECRET_KEY` | `kybase` / `kybase-dev-secret` | MinIO 凭据 |
| `KYLAB_S3_BUCKET` | `kybase` | 对象存储桶 |
| `KYLAB_URL_SIGNING_SECRET` | 空 | 下载与页图签名；留空时首次 setup 自动生成 |
| `KYLAB_PUBLIC_BASE_URL` | 空 | REST 对外基址，用于返回绝对下载地址 |
| `KYLAB_MCP_PUBLIC_URL` | 空 | MCP 对外地址，用于管理台接入片段 |
| `KYLAB_RUN_WORKER` | `true` | 后端内嵌摄入队列消费者 |
| `KYLAB_WORKER_CONCURRENCY` | `1` | 摄入并发，1–8 |

`KYLAB_PUBLIC_BASE_URL` 与 `KYLAB_MCP_PUBLIC_URL` 留空不影响服务启动，
只是响应里不出现绝对链接、管理台「接入」页需要手动填写地址。

完整变量表见 `backend/.env.example` 与 `backend/app/core/config.py`。

### 1.2 反向代理与 TLS

生产环境建议在 `frontend` 前放一层 Nginx、Caddy 或 Traefik，终止 TLS 并转发到
`127.0.0.1:8080`；MCP 用单独域名或端口转发到 `127.0.0.1:8765`。
证书与域名确定后，把 `KYLAB_PUBLIC_BASE_URL`、`KYLAB_MCP_PUBLIC_URL` 写成外部地址。
管理台与 API 同源，不需要额外配置 CORS。

## 2. 首次使用

1. 打开管理台，创建管理员账号。
2. 进入「模型」页，登记一个嵌入模型（OpenAI 兼容接口、模型名与维度）。
   未登记时无法创建知识库。
3. 进入「API 密钥」页，创建一把 Key。建议给 Agent 只读或指定库/工具的 Key。
4. 把 MCP 地址与 Key 填入客户端：

```json
{
  "mcpServers": {
    "kybase": {
      "type": "http",
      "url": "http://<your-host>:8765/mcp",
      "headers": { "Authorization": "Bearer <API Key>" }
    }
  }
}
```

也可以用 stdio：

```bash
cd backend
python -m app.mcp_server.server --transport stdio
```

stdio 模式从环境变量 `KYLAB_MCP_KEY` 读取 Key。

## 3. 使用已有的 PostgreSQL 与对象存储

如果机器上已有 PostgreSQL（需安装 `vector` 扩展）与 S3 兼容存储，可以只启动应用层。
以 `deploy/docker-compose.yml` 为模板，删掉 `postgres`、`minio`、`minio-init` 三个服务，
并把后端环境改为：

```dotenv
KYLAB_DATABASE_URL=postgresql://<user>:<password>@<host>:5432/<database>
KYLAB_S3_ENDPOINT=https://<s3-endpoint>
KYLAB_S3_ACCESS_KEY=<access-key>
KYLAB_S3_SECRET_KEY=<secret-key>
KYLAB_S3_BUCKET=<bucket>
KYLAB_S3_SECURE=true
```

对象存储也可以省略：清空 `KYLAB_S3_*` 后，原件落在 `KYLAB_DATA_DIR` 下的
`originals/`、`markdown/`、`images/`。

数据库需要预先创建；schema 与迁移由应用在启动时完成，不需要手工执行 SQL。
建议先在测试库验证连接与备份流程。

## 4. 验证

```bash
# 健康检查
curl -s http://localhost:8080/api/v1/health

# OpenAPI
curl -s http://localhost:8080/api/v1/openapi.json | head

# MCP 工具清单（在 backend 目录、已安装依赖时）
python -m app.mcp_server.server --list-tools
```

`--list-tools` 最后一行是工具面指纹 `surface_fingerprint`。工具面变化时指纹会更新，
可用于判断客户端是否需要同步升级。

## 5. 升级

```bash
cd kybase
git pull --ff-only
docker compose -f deploy/docker-compose.yml up -d --build
```

升级前先备份（见下一节）。数据库迁移在应用启动时自动执行；跨大版本升级前请先在
测试环境验证备份与恢复。

## 6. 备份与恢复

- **PostgreSQL**：用 `pg_dump` / `pg_dumpall` 导出。
  ```bash
  docker compose -f deploy/docker-compose.yml exec postgres \
    pg_dump -U kybase kybase > backup-$(date +%F).sql
  ```
- **对象存储**：备份 `kybase-objects` 卷或 S3 桶。对象写入后不再修改，增量备份即可。
- **DuckDB / 数据目录**：备份 `kybase-data` 卷。

恢复时先停应用，再恢复数据库与对象存储，最后启动应用。不要直接复制运行中的
PostgreSQL 数据目录。

## 7. 常见问题

| 现象 | 检查 |
|---|---|
| 启动后 `/api/v1/health` 不通 | `docker compose ps` 看 backend 是否 healthy；`docker compose logs backend` |
| 创建知识库被拒 | 先在「模型」页登记嵌入模型 |
| 上传后一直不处理 | 确认 backend 的 `KYLAB_RUN_WORKER=true`，看任务中心与日志 |
| MCP 连不上 | 确认 `mcp` 容器在运行、8765 端口可达；HTTP 请求需带 Bearer Key |
| 401 | 检查 API Key 是否有效、是否包含目标库的权限 |
| 下载链接或页图为空 | 配置 `KYLAB_PUBLIC_BASE_URL` 与签名密钥 |
| 前端 502 | backend 尚未 healthy；等健康检查通过后刷新 |

## 8. 已知限制

- 版本线仍为 `0.1.0`。完整栈 compose 建议先在测试机做一次端到端验证，
  再放到生产环境。
- 表格副本（DuckDB）是单文件单写者；多副本部署前需要改造。
- 环境变量前缀与 API Key 前缀沿用 `KYLAB_` / `kylab_`，用于兼容早期版本；
  后续大版本会单独规划迁移。
- 对象存储与数据库均为外部依赖，请自行配置备份、监控与访问控制。

## 9. 卸载

```bash
docker compose -f deploy/docker-compose.yml down
```

`down` 不会删除数据卷。确认不再需要数据后，再显式删除：

```bash
docker compose -f deploy/docker-compose.yml down -v
```
