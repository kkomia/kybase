# kybase 知识库 Skill

让 Agent 能查你自己的知识库（kybase），并**拿到可追溯的原文出处**。

> 目录名仍是 `kylab-knowledge-base`，脚本仍叫 `kylab_query.py`——技能包名与它被安装
> 到别处时的路径沿用原名；环境变量与凭据前缀同理保留 `KYLAB_` / `kylab_sk_`。

## 它做什么

kybase 的核心能力是**带出处的检索**：返回的是你文档里的原文片段
（含文档名、页码、标题路径），不是一段生成的回答。

这个区别是这个 Skill 存在的理由：需要**核对**答案时，原文是证据，摘要不是。
所以无论是 MCP 工具还是本目录的脚本，给出的都是片段而不是总结。

**但片段之前先有一句判定。** 每次检索的返回都**以一句判定开头**（`summary`），
跟着是完整分布（`distribution`）与"这次按什么收敛的"（`decision`），`hits` 在它们之后。
判定的关键是 `fit`：`strong` 很对得上 / `weak` 只对上一部分 / **`none` 这份资料答不了**
（这时如实说"资料里没有"，别拿那几条片段编答案）/ `unknown` 这个库的嵌入模型没标定过、
判不了。命中太多就**按分布收敛**而不是全塞进上下文：`keep`（1–20）、`min_score`
（绝对余弦）、`per_doc`（每篇最多几条）三个旋钮在 MCP 与脚本两条路上同名同义。

## 两条接入路径

| 路径 | 适合 | 怎么用 |
|------|------|--------|
| **MCP** | 支持 MCP 的客户端（Claude Desktop、Cursor 等） | 见 `SKILL.md` 里的配置片段 |
| **脚本** | 只会 shell 与 HTTP 的运行环境 | `python scripts/kylab_query.py --query "…"` |

两条路走的是**同一套检索**，只是传输不同。不是所有运行环境都能说 MCP，
而 shell 与 HTTP 几乎哪里都有——所以两条都提供。

## 快速自检

> 下面的地址是**本机默认值**；线上那套跑在 NAS 上：REST `http://192.168.31.18:8081/api/v1`、
> MCP `http://192.168.31.18:8765/mcp`（**别的部署以部署方给的为准**）。

```bash
# 1) 后端在跑吗
curl -s http://127.0.0.1:8000/api/v1/health

# 2) MCP 工具认得出来吗（在 kybase 仓的 backend 目录下跑；需要先装 mcp extra）
cd backend && python -m app.mcp_server.server --list-tools

# 3) 脚本能查到东西吗（v0.11 起接口一律要凭据）
KYLAB_API_KEY=... python scripts/kylab_query.py --list
KYLAB_API_KEY=... python scripts/kylab_query.py --query "眼轴怎么监测"
```

> 凭据怎么来：在控制台侧栏的「API 密钥」页建一把**只读**密钥即可
> （查文档不需要读写档）。登录会话令牌只属于浏览器，别拿来配脚本。

## 三个容易踩的点

1. **注册数据源不会立刻抓取。** `add_data_source` 只是登记，
   要等定时任务或在控制台点「立即拉取」。
2. **未 `indexed` 的文档搜不到。** 上传后处理是异步的；
   搜不到时先用 `get_document_status` 看它到哪一步了，别急着说"没有这份资料"。
3. **删文档不可当场撤销。** 原文进回收站保留 7 天，
   但切块与向量**立即清除**——所以删完立刻就搜不到了。

## 安全

工具能读**也能删**文档，所以**每一次工具调用都要凭据**——没有匿名放行。

- **HTTP 模式**：每个请求带 `Authorization: Bearer <API Key>`（v0.12 起强制；
  头名大小写不敏感）。在此之前这条链路没有身份，不带凭据即可列出全部知识库，
  而同一进程还挂着删除。
- **stdio 模式**：那条传输没有请求头，凭据由客户端拉起本进程时放进环境变量
  `KYLAB_MCP_KEY`。
- 两者都没有 → **一律拒绝**。握手与工具清单仍能列出来（否则客户端连不上、
  排障时一点线索都没有），但每个工具调用都会被拒并说明缺哪份凭据。

判定复用后端同一套账号/API Key 服务，不是另写一套：所以 Key 的作用域就是它的
边界——绑库的 Key 只看得见、写得动那几个库，只读 Key 不能上传、入库、删除。
钥匙还能**只放开一部分工具**（比如只给 `search`）：范围外的工具连 `tools/list`
都列不出来，调用时也会被当场拒绝。库范围与工具范围**留空都表示不限**，
只有权限档必须选只读或读写。

默认只监听 `127.0.0.1` 仍然是有意的；确实要在局域网上开，请只放在可信网络里
——**工具集里含删除**。
